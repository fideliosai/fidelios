# v0.0.53

> Released: 2026-05-25

Two rendering fixes for the symptom reported in FID-58: agents on the Codex
adapter write comments and descriptions whose Markdown carries literal `\n`
escape sequences instead of real newlines, so the UI showed the raw escapes
instead of formatted text.

## Escaped newlines in rendered comments

[#100](https://github.com/fideliosai/fidelios/pull/100) — comment bodies that
contained literal `\n` (and HTML entities such as `&#x20;`) rendered the raw
escape characters rather than line breaks.

- `MarkdownBody` now normalizes literal `\n` / `\r\n` sequences into real
  Markdown line breaks before rendering, while leaving inline code and fenced
  code blocks untouched so legitimate escapes inside code survive verbatim.
- Added regression coverage for the Codex-shaped comment payload from FID-58.

## Inline descriptions rendered as Markdown

[#101](https://github.com/fideliosai/fidelios/pull/101) — issue descriptions
still surfaced stored Markdown as raw text, so the same literal-`\n` artifacts
appeared in the issue body even after the comment fix.

- The multiline `InlineEditor` display mode now renders through `MarkdownBody`,
  reusing the same escaped-newline / entity normalization. Edit mode keeps the
  existing Markdown editor.
- The editor stays open if a save rejects, so an autosave error is surfaced
  instead of silently resetting the draft to its previous value.
- Added regression coverage for issue-description-shaped content.

## Internal

- PRs [#100](https://github.com/fideliosai/fidelios/pull/100) and
  [#101](https://github.com/fideliosai/fidelios/pull/101) merged off `main` with
  green CI (`policy`, `verify`, `e2e`) and Code Reviewer approval.
- Changes are confined to `ui/src/components/MarkdownBody.tsx` and
  `ui/src/components/InlineEditor.tsx`, with new tests in
  `MarkdownBody.test.tsx` and `InlineEditor.test.tsx`.
