# v0.0.54

> Released: 2026-05-28

Bug fix for FID-64: agents (CMO on TRA-90) were silently reading zero new
comments and stopping replies, even when comments were present.

## Fix: comment cursor 500 silenced agent replies

[#105](https://github.com/fideliosai/fidelios/pull/105) — the `?after=`
comment-cursor query bound a bare JavaScript `Date` into a raw Drizzle `sql`
template. The postgres driver cannot bind a `Date` in an untyped param slot,
producing a `Buffer.byteLength … Received an instance of Date` 500 error.
Agents interpreted the 500 response as "zero new comments" and exited without
replying, causing the symptom of an agent appearing unresponsive to @-mentions.

- Introduced `commentCursorCondition(anchor)` helper in
  `server/src/services/issues.ts` that wraps the anchor lookup in a correlated
  subquery, avoiding any direct Date binding.
- Applied the helper to all three `listComments` cursor paths (default,
  ascending, descending).
- Added four focused regression tests covering the boundary conditions.
